# payment-service: локальная оплата

Имитация провайдера работает внутри payment-service и доступна сразу после запуска.
Платёж подтверждается кнопкой «Оплатить» или «Отклонить». Настоящие списания не выполняются.

## Запуск

Из корня проекта:

```powershell
docker compose up -d --build --wait payment-service
```

Также можно запустить приложение из IDE. Нужны существующие payment-postgres и Kafka.
Базовый публичный адрес задаётся через
`PAYMENT_PUBLIC_URL` (по умолчанию `http://localhost:8083`); при смене порта измените и адрес.

## Проверка

1. Откройте [Swagger UI](http://localhost:8083/swagger-ui/index.html).
2. Выполните `POST /api/mock/payments` через `Try it out`: укажите UUID платежа, заказа
   и пользователя, номер попытки, сумму, валюту и `expiresAt` в будущем.
3. Откройте `checkoutUrl` из ответа и выберите «Оплатить» или «Отклонить».
4. Статус можно проверить через `GET /api/mock/payments/{id}` в том же Swagger UI.

- Создание сохраняет `PENDING` и `PaymentSessionCreated` в одной транзакции.
- «Оплатить» сохраняет `SUCCEEDED` и `PaymentSucceeded`, «Отклонить» — `FAILED` и `PaymentFailed`.
- Подтверждение после `expiresAt` даёт `FAILED` с кодом `SESSION_EXPIRED`.
- Повторное нажатие после завершения сохраняет первый результат и не создаёт новых событий.
- Повтор создания с тем же `paymentId` и теми же данными возвращает сохранённый платёж,
  в том числе после истечения срока. Изменённые данные дают 409.
- Ограничения БД запрещают вторую активную попытку и новую оплату уже оплаченного заказа.
  После отказа можно создать новую попытку с новым `paymentId` и следующим `attemptNumber`.
- Существующий publisher отправляет события из outbox в `payment.events` с ключом `orderId`.
  При недоступной Kafka события остаются в БД для повторной отправки.

Платёж и outbox сохраняются в существующей БД payment-service и переживают перезапуск.
При одновременном создании одинаковых запросов один из них может получить 409;
повтор запроса возвращает уже созданный платёж.

Сейчас создание запускается вручную через локальный endpoint. Обработку команд
от order-service и возвраты добавим следующими этапами. Названия существующих событий сохранены.
